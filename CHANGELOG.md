# История изменений

## 2.5 (2026-11)

- `platformRoot` в конфиге роли: каталог, где лежат версии платформы, если 1С установлена не в
  `C:\Program Files\1cv8`. Кроме него агент сам добавляет каталог платформы запущенного в сеансе
  `1cv8`. Если платформа не найдена, в причине отказа перечислены найденные на дисках `1cv8.exe`,
  чтобы было что вписать в `platformRoot`;
- `dump-dt -NoKill`: `DumpIB` без снятия сеансов и без `rac`, для сервера, где агенту недоступно
  администрирование кластера. Если база занята, `DumpIB` откажет сам.

## 2.4 (2026-11)

- запрет новых сеансов и регламентных заданий на время `pull`, `test` и `update-prod -Mode full`
  (`rac infobase update --sessions-deny --scheduled-jobs-deny` с кодом разрешения `denyCode`,
  по умолчанию `DEPLOY`). Агент сам ходит в базу с `/UC <код>` и снимает запрет в `finally`,
  даже если команда упала. Без запрета толстые клиенты и роботы переподключались за секунды после
  `kill-sessions` и срывали `UpdateDBCfg` «Ошибкой исключительной блокировки». Если запрет не
  ставится, команда не начинается;
- снятие сеансов ждёт их фактического завершения до 60 с, повторяя `terminate` каждые 10 с.
  Один замер через 2 с считал закрывающиеся сеансы оставшимися и срывал полное обновление;
- `update-prod -Objects <objects.xml>`: из хранилища забираются только объекты из списка
  (`ConfigurationRepositoryUpdateCfg -objects`), например чужой модуль, пока свои объекты ещё
  не приняты. Без `-Objects` по-прежнему всё хранилище, последний `objects-*.xml` не подставляется;
- файловые базы: при пустом `server1c` в конфиге роли агент подключается к `ib` как к каталогу
  (`/F`), `com-check` без `-Server1c` с путём в `-Ib` проверяет файловую базу без TCP.

## 2.3 (2026-11)

- агент пишет в `agent-status.json` поля `running` (id команды), `started` и `limit` в начале
  каждой команды и очищает их в конце. Срок берётся из поля `waitSec` команды (его ставит
  `deploy.ps1`, это его `TimeoutSec`), иначе 21600 с;
- `deploy.ps1` при heartbeat старше 3 минут смотрит на эти поля: агент занят и укладывается
  в срок (с запасом 120 с), значит, команда встаёт в очередь; агент свободен или его команда
  просрочена, значит, выход с кодом 2 сразу, без ожидания таймаута. С агентом старше 2.3 только
  предупреждение. `status` показывает, чем занят агент;
- раньше команда, отправленная неработающему агенту, ждала весь таймаут (90–300 с), а отбить её
  по одному возрасту heartbeat было нельзя: у занятого агента heartbeat тоже старый.

## 2.2 (2026-09)

- команды `repo-report` и `repo-dump` — чтение хранилища без изменения базы. `repo-report
  -NBegin <N> [-NEnd <M>]` даёт историю версий (кто, когда, какие объекты помещал) текстом в
  ответе и файлом в `artifacts`; `repo-dump -Version <N>` выгружает конфигурацию заданной
  версии в `.cf`. Предназначены для случая, когда объединение затёрло чужую правку: `repo-report`
  показывает, что перед `test` в хранилище были чужие версии, `repo-dump` достаёт затёртый
  объект из его прежней версии;
- README: в разделе «Что выяснилось на практике» описан риск затирания обычной формы при
  устаревшем `release.cf` (двоичная форма сливается целиком) и приём сверки истории перед `test`;
  добавлены заметки про «База данных не открыта» из-за зависших `1cv8.exe` на файле хранилища
  и про несовпадение версии платформы с кластером.

## 2.1 (2026-09)

- команда `repo-bind` и автоматическое восстановление связи базы с хранилищем: шаг упал →
  агент разбирает текст ошибки платформы → `BindCfg -forceBindAlreadyBindedUser` → один повтор
  шага. Встроено в `pull`, `test`, `commit`, `unlock`, `update-prod`; `-forceReplaceCfg` —
  только внутри `pull` и только вне роли `prod`;
- видимый прогресс долгих шагов: счётчик «шаг: идёт, N с» раз в 10 секунд, пока работает
  пакетный Конфигуратор, и проценты при копировании `.cf` и `.cfe` (Copy-Item прогресса не даёт,
  а через канал RDP копирование идёт минутами и выглядит зависанием). В файл лога идут только
  начало, четверти и итог;
- `rac session terminate` с ответом «Сеанс не найден» больше не считается ошибкой: это гонка,
  сеанс закрылся между получением списка и снятием.

## 2.0 (2026-09)

Первая публичная версия. Обезличенная и причёсанная редакция агента, который с июля 2026
обслуживает три контура: тестовый сервер с хранилищем, боевая база за шлюзом удалённых
рабочих столов и бухгалтерия без хранилища.

Что изменилось относительно внутренней версии 1.19:

- роль определяется по `hostPattern` из конфига, а не по зашитым именам машин;
- папка обмена задаётся параметром `-ShareRoot` (агент) и `-Root`/`DEPLOY_ROOT` (оркестратор);
- три обёртки над `1cv8 DESIGNER` сведены в одну, `ras`/`rac` вынесены в общий контекст;
- папки обмена MCP и имя обработки берутся из конфига, а не из таблицы в коде;
- транспорт MCP через тонкий клиент с `/Execute` удалён: форма обработки при таком запуске
  не открывается, остался только демон по COM;
- `mcp-daemon.vbs` хранится в UTF-8, агент конвертирует его в ANSI перед запуском;
- оркестратор сам отказывает в командах хранилища цели без `repoPath`;
- исключение внутри команды возвращается ответом `error`, а не роняет цикл;
- поиск других экземпляров агента смотрит на `-File …deploy-agent.ps1`, а не на любое
  упоминание имени в командной строке PowerShell;
- каталог локальной копии обработки MCP вынесен в конфиг (`mcpLocalDir`);
- в ответ `kill-sessions` добавлено число оставшихся сеансов, когда снять всех не удалось;
- папка `examples/` с обезличенными файлами команд, ответов, `objects.xml`, `MergeSettings.xml`
  и консольным сеансом доставки.

Внутренняя история до 2.0 (для контекста): v1.11 `com-check`; v1.13 `load-cf`;
v1.14 `mcp-start`/`mcp-stop`/`mcp-list` через COM-демон; v1.15 `build-epf`, `peek`,
`windows`, `screenshot`, `com-exec`; v1.17 `fetch`; v1.18 роль без хранилища
(`ext-list`/`ext-dump`/`ext-install`/`dump-cf`/`dump-dt`), `platformVersion: auto`;
v1.19 `repo-unbind`, учёт тонкого клиента в `windows`/`mcp-list`.
